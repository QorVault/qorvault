## 1. `.env` credential repair (ksd-main copy only)

### What was wrong

The diagnostic reported that `.env`'s `POSTGRES_PASSWORD` failed authentication against
the container, forcing every query through `podman exec`. The assumption was that the
credential was stale.

It was not stale. Comparing the two values by SHA-256 (without printing either):

| Source | Length | SHA-256 (first 12) |
|---|---|---|
| Container `POSTGRES_PASSWORD` | 13 | `a6a775f61e77` |
| `.env` `POSTGRES_PASSWORD` (before) | 32 | `6f7f2f77cd2e` |

A 32-character value versus a 13-character one is not a typo, a truncation, or a rotation
that half-landed. These are **two unrelated credentials**. The `.env` file was carrying a
secret belonging to something else — most plausibly a generated production credential that
was written into the development `.env` by mistake.

**Why this matters beyond the inconvenience:** the working credential is `13` characters
and is stored *in plaintext in the quadlet unit file*
(`~/.config/containers/systemd/civic-postgres.container`, `Environment=POSTGRES_PASSWORD=`).
Until this session it was also reachable from the LAN (§2). A short plaintext credential on
an all-interfaces database bind is the weakest link in this setup, and fixing the bind
address does not fix the credential.

### What was changed

Exactly one line of `~/workspace/projects/ksd-main/.env` was rewritten in place. The file
had 8 lines before and 8 after; the other 7 keys (`POSTGRES_HOST`, `POSTGRES_PORT`,
`POSTGRES_DB`, `POSTGRES_USER`, `ANTHROPIC_API_KEY`, `QDRANT_URL`, `RESEND_API_KEY`) were
not touched. The new value's hash matches the container's (`a6a775f61e77`).

No backup copy of `.env` was created. An attempt to make one was declined by the operator
mid-session, which was the correct call — a `.env.bak` would have duplicated a live secret
onto disk with no access control. **The overwritten 32-character value is therefore not
recoverable from this session.** It is identifiable only by its hash prefix `6f7f2f77cd2e`.
If it was a real production credential, it still exists wherever it was originally issued;
if it was the only copy, it is gone. Flagged as an operator open item.

### Verification

Host-side, with `.env` loaded — the exact check that failed in the diagnostic:

```
$ set -a; source .env; set +a
$ PGPASSWORD="$POSTGRES_PASSWORD" psql -h "$POSTGRES_HOST" -p "$POSTGRES_PORT" \
    -U "$POSTGRES_USER" -d "$POSTGRES_DB" -tAc 'select 1'
1
exit=0
```

**Result: success.** `podman exec` is no longer required for host-side tooling.

The `.env` in the guarded tree (`ksd-boarddocs-rag`) was **not** touched, per instruction.

## 2. PostgreSQL bind address

### Discovery

`boarddocs-postgres` is defined by a **systemd quadlet**, not compose and not plain
`podman run`:

```
~/.config/containers/systemd/civic-postgres.container
```

Note the filename/container-name mismatch: the unit is `civic-postgres.container` and the
systemd unit is `civic-postgres.service`, but the container it creates is named
`boarddocs-postgres`. Anyone grepping for a `boarddocs-postgres` unit file will not find
one. Worth renaming for operational clarity, but not changed here.

The offending line, before:

```ini
PublishPort=0.0.0.0:5432:5432
```

Confirmed at the socket level before the change:

```
$ ss -ltnp | grep 5432
LISTEN 0 128 *:5432 *:* users:(("pasta.avx2",pid=2197,fd=74))
```

`*:5432` — all interfaces, as reported. Every other service on the host
(`qdrant`, `vllm`, `open-webui`) binds `127.0.0.1` correctly; Postgres was the sole
exception, and it is the one holding the corpus.

**Firewall state could not be determined.** `firewall-cmd --state` and `--list-ports`
both returned `Authorization failed` — they require root, and this session is user-level
only. So whether the LAN could actually reach 5432, or whether a host firewall was
silently absorbing the risk, **remains unverified**. This is an operator item; the bind
fix is correct regardless, but the exposure window cannot be sized without it.

### Pre-restart connection check (stop-rule)

```

               (pid = pg_backend_pid()) AS is_me, backend_start
               FROM pg_stat_activity WHERE datname = current_database();"
```

One connection, `is_me = t` — my own session. A widened check across **all** databases
returned the same single row. No foreign connection existed, so the stop-rule did not
trigger and the restart was safe.

### Change and verification


Then `systemctl --user daemon-reload` and `systemctl --user restart civic-postgres.service`.

### Rollback and a caution

If any machine on the LAN was connecting to this database — the diagnostic notes the
operator works from a separate Framework Desktop — **that connection is now broken by
design**. Nothing was connected at the time of the change, so nothing in flight was
interrupted, but a scheduled or intermittent LAN client would fail on its next run.

To roll back, set `PublishPort` back to `0.0.0.0:5432:5432`, `daemon-reload`, restart. The
correct fix for a legitimate LAN client is an SSH tunnel, not an all-interfaces bind.

### Step 1 — credential repair

```bash
# Compare container vs .env credential WITHOUT printing either value
cd ~/workspace/projects/ksd-main
CPW=$(podman inspect boarddocs-postgres \
      --format '{{range .Config.Env}}{{println .}}{{end}}' \
      | grep '^POSTGRES_PASSWORD=' | cut -d= -f2-)
EPW=$(grep '^POSTGRES_PASSWORD=' .env | cut -d= -f2-)
echo "container pw: len=${#CPW} sha256=$(printf %s "$CPW" | sha256sum | cut -c1-12)"
echo ".env      pw: len=${#EPW} sha256=$(printf %s "$EPW" | sha256sum | cut -c1-12)"
grep -E '^POSTGRES_(HOST|PORT|DB|USER)=' .env

# In-place single-line rewrite; asserts exactly one match; prints only hashes
CPW="$CPW" python3 - <<'PY'
import os, hashlib
pw = os.environ["CPW"]
lines = open(".env").readlines()
hits = 0
for i, ln in enumerate(lines):
    if ln.startswith("POSTGRES_PASSWORD="):
        old = ln.split("=", 1)[1].strip()
        lines[i] = f"POSTGRES_PASSWORD={pw}\n"
        hits += 1
assert hits == 1, f"expected exactly 1 POSTGRES_PASSWORD line, found {hits}"
open(".env", "w").writelines(lines)
h = lambda s: hashlib.sha256(s.encode()).hexdigest()[:12]
print(f"replaced 1 line. old sha256={h(old)} len={len(old)} -> new sha256={h(pw)} len={len(pw)}")
PY

# Confirm keys intact, values redacted
sed -E 's/^([A-Z_]+)=.*/\1=<redacted>/' .env

# Verification
set -a; source .env; set +a
PGPASSWORD="$POSTGRES_PASSWORD" psql -h "$POSTGRES_HOST" -p "$POSTGRES_PORT" \
```
